Autenticación sin cookies

El login emite un JWT HS256 de 20 min con user_id y role_id. No hay sesión por cookie: cada petición viaja con Authorization: Bearer <JWT>.

Política de fallo asimétrica

fail-CLOSED sesión, revocación y autorización: si Redis cae → 503, nunca se acepta un token dudoso.
fail-OPEN caché de catálogo: si Redis cae, se sirve desde PostgreSQL.

Autorización por método

GET/HEAD/OPTIONS pueden ser públicos (catálogo); el resto exige Bearer. 401 si falta o es inválido el token; 403 si el rol no alcanza.
